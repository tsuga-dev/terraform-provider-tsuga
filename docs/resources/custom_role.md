# tsuga_custom_role (Resource)

Custom global role granting its holders access to Tsuga assets within a team scope, and to telemetry signals

## Example Usage

```terraform
resource "tsuga_custom_role" "example" {
  name        = "platform-on-call"
  description = "Edits monitors and dashboards of the platform team, and reads its production telemetry."

  team_scope = {
    type     = "specific"
    team_ids = ["abc-123-def"]
  }

  assets = {
    team             = "read"
    dashboard        = "write"
    monitor          = "write"
    "monitor-folder" = "read"
  }

  telemetry = ["log", "metric", "trace"]

  telemetry_query = [
    {
      key    = "context.env"
      values = ["production"]
    }
  ]
}
```

## Schema

### Required

- `assets` (Map of String) Access level granted per resource type, within the role team scope. An omitted resource type grants no access.
- `name` (String) Human-readable custom role name, unique across the account.
- `team_scope` (Attributes) Teams the role grants its asset permissions on. `all` covers every team, `public` covers public teams only, `specific` covers the listed teams, and `all-except` covers every team but the listed ones. (see [below for nested schema](#nestedatt--team_scope))
- `telemetry` (Set of String) Telemetry signals the role can read. An empty array grants no telemetry access.

### Optional

- `description` (String) Free-form description of the custom role. Absent when not set.
- `telemetry_query` (Attributes List) Additional restriction applied cluster-side to every telemetry query the role holder runs. Each entry keeps only the data points whose `key` matches one of `values`, and entries are combined with AND. (see [below for nested schema](#nestedatt--telemetry_query))

### Read-Only

- `id` (String) Tsuga-generated custom role ID assigned at creation.
